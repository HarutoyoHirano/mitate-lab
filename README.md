# mitate-lab（見立てラボ）

**同じに見える。でも、測り方を変えると違う。**

平均や「最後の一つの数字」だけで「同じ」と判定すると、時間の中で起きている違いを見落とします。これは医療の測定でも、ものづくりの検査でも起きることです。見立てラボは、物理を深く学ばずに医療系へ進んだ学生が、この見落としを**自分の手で見破り、なぜ違うのかを式を書かずに説明できるようになる**ための教材ゲームです。

検査ロボが「区別できません」と言った試作品の、見落としを見つけるゲームです。膝の人工軟骨・人工血管・神経の膜という三つの体の部品を、ばね・ダンパ、電気の部品（コンデンサ・抵抗・電流を送りこむもの・電池）に**見立て**、物理・化学・生物を一つの見方でつなぎます。最後に、同じ部品でほかの臓器の謎を **Claude が組み立て、計算プログラムが確かめて**、続きとして遊べます。

> Built with Claude: Japan 2026 提出作品（テーマ1「あなたにしかない深さを」）。チャットボットではなく、医療の助言もしません。ラボ・試作品・検査ロボは架空で、値は模型の値です。

## 審査員の方へ（見どころと近道）
- **すぐ遊ぶ（ログイン不要）**：https://harutoyohirano.github.io/mitate-lab-play/ 。謎1を通すと、予想→測る→見落としの証拠→なぜ？（4つの説明を自分で選び、計算プログラムが確かめる）→正体、の一周が分かります
- **Claude の見どころだけ見る**：タイトルの一覧で「まとめ・つづきの謎」を押し、心臓・肺・体温のどれかを選ぶ。Claude が組み立てた謎を、計算プログラムが15項目で確かめてから遊ばせます（このページでは、確かめに通った Claude の出力の記録を使います）
- **Claude がその場で組み立てる版**：claude.ai の公開ページ（https://claude.ai/artifact/4y2W7jYxQRJA3s8q6Kr7gi 、claude.ai へのログインが必要）では、開いた人の Claude が題材から謎を組み立て、確かめに落ちれば理由を返して作り直させるところまで、その場で動きます
- **作品の核**：AIに謎を**組み立てさせ**、プログラムが基準に照らして**確かめ**、落ちたら**理由を返して作り直させる**。AIの出力を、確かめないまま学生に見せない仕組みを、作品の中心に置いています（下の「作品の中の Claude」）

## なぜ作ったか
体のしくみの多くは、力学と電気の言葉で書けます。けれど、高校で科目「物理」（「物理基礎」とは別の科目）まで履修する生徒は多くありません（公立高校の平成25年度入学者の抽出調査で、「物理」の履修は16.2%、普通科等で22.8%。文部科学省 理科ワーキンググループ資料8、2016）。作者は医療系の大学で工学を教えていて、「物理」を履修せずに入学してくる学生を多く見てきました（人数を数えた調査ではなく、作者の実感です）。式から入ると、ここで止まってしまいます。

作者の専門は血管の粘弾性（押すと時間をかけて形が戻る性質）です。研究で毎日見ている「一つの数字だけでは見落とす違い」と「同じ式が別の臓器にも出てくる」ことを、式を書かずに、手で動かして見つけられる形にしました。

## どんな体験か
一画面の舞台で、下のメッセージ窓にロボ・案内・計算プログラムの言葉が出て、行動は二つか三つから選びます。各謎の前に、これからの謎を伝える短い導入ムービー（見本の値だけで描き、答えの手がかりは見せない）が流れます。

1. **謎1 軟骨の見落とし**
   - **見破れ**：ロボは「押して20秒後の力」だけで見分ける。膝の試験機で見本Aと毎回ちがう隠れた試作品Bを走らせ、へこみが分かれる瞬間を証拠としてロボに見せる。試験台で力を記録し、四つの説明に「合う／合わない／分からない」を選んでから、計算プログラムがまとめて確かめる。正体は、やさしい説明→ばね・ダンパの見立て→Bはどこにあたる性質が違ったか、の三段
   - **仕掛けろ**：今度はあなたが、ロボの見る一点だけ見本とそろえ、別の点には違いを残す試作品をつまみ二つでつくる。ラウンド2でロボが見る場所を変え、前の設計は通らない
   - **鍛えなおす**：ロボは自分では手順を書きなおせない。あなたが見る数字を足し、計算プログラムが「すり抜ける試作品が残らないか」を（つまみの範囲の格子で数えて）確かめる。通ったら、仕掛けろで自分がつくって通った試作品を新しい手順で検査しなおし、「前はすり抜けた→今は見分けた」を見せる
2. **謎2 脈の見落とし（人工血管）**：ロボは「1回の脈の平均の圧」だけを見る。平均は出口の流れにくさだけで決まり、血管のふくらみやすさにはよらない。脈の中の高い圧と低い圧で見落としを示し、試験装置のつまみで同じ脈をつくって正体を確かめる。正体は、①ポンプ ②ふくらむ袋 ③細い管の見立てと、同じ形の式になる電気の部品で見なおす（「もし①や③が違ったら？」も切りかえて見られる）
3. **謎3 膜の見落とし（神経の膜）**：膜は本当に電気をためる。離す直前の電圧が同じでも、上がり方と戻り方が違う。正体は電気回路（コンデンサ・抵抗・電流を送りこむもの・電池）で、上がりきる高さ＝電流×抵抗、かかる時間＝抵抗×ためやすさ、と言葉の式で見る
4. **まとめ**：軟骨・血管・膜は、同じ種類の部品（ためる・流れにくさ・送りこむ＋電池）の組み合わせで書けた（つなぎ方はそれぞれ違う。軟骨はばね二つとダンパ一つ、血管と膜はためる部品一つと流れにくさ）。軟骨と血管は式の形が同じだけ、膜は本当に電気、と書き分ける
5. **つづきの謎（Claude が組み立てる）**：「同じ部品で、ほかの臓器も組み立てられる？」 題材（心臓・肺・体温など）を選ぶか、名前を入れると、Claude が模型の形ごと組み立て、計算プログラムが確かめ、通ったものを謎1〜3と同じ舞台で遊べる（下の「作品の中の Claude」）

ロボの自信ゲージは謎を解くたびに減り、鍛えなおすと戻ります。プレイヤーの減点・順位・回数の記録はありません。進み具合だけをこの端末のブラウザに自動で保存し、名前などの個人の情報は入力も保存もしません。

## 作品の中の Claude：謎を組み立てる係と、確かめる計算プログラム
AIが役に立つのは、用意した問いの**続き**を、物理・化学・生物をまたいでつくるところだと考えました。Claude を外しても、用意した謎1〜3は遊べます。けれど新しい題材の模型・ロボが見る数字・物語は、先生が一から組み立てることになります。教材を一人でつくると、題材は作者が知っている範囲で止まります。Claude に部品箱から模型ごと組み立てさせれば、学生が「次は心臓は？」と思った題材の続きを、その場で用意できます。ただし、AIの書いた模型や引用をそのまま学生に見せることはしません。**組み立てるのは Claude、確かめるのはプログラム**、と分けています。

- **部品箱から模型を組み立てる**（`server/model/partsNet.ts`）：ためる部品・自分で固くなる部屋・流れにくさ・一方通行の戸・送りこむもの・高さの決まった場所。Claude はつなぎ方・値・体の何にあたるか・ロボが見る一つの数字・Bはどの部品が違うか・導入ムービーの三つの場面・前の謎からのつなぎを書く。形をこちらで決めないので、心臓なら「自分で縮む部屋と二つの戸」を Claude が自分で選ぶ
- **計算プログラムが15項目を確かめる**（`verifyNetPuzzle`）：組み立てた形のまま計算し、つなぎ方・逃げ道・計算の破綻・ロボの数字では本当に区別できないか・別の時刻なら本当に違いが見えるか・病気や治療につながる言葉がないか、などを見る。ロボの数字がそろわなければ、Claude が指定した値をプログラムが二分法で合わせる
- **出典はカタログからだけ**（`server/model/refs.ts`）：AIの書く引用は架空の文献になりうるため、作者が出版社・PubMed・Crossref で書誌を確かめた23件だけを並べ、部品ごとに id で選ばせる。文献ごとに「支える部品の種類」「扱っていないこと」「対象の言葉」を持たせ、合わない使い方は落とす。画面には部品ごとの出典を出す
- **落ちたら、理由を返して一度だけ作り直させる**：画面で、1回目の確かめの板（落ちた行を赤く、「不合格」）→「落ちた理由を Claude へ戻す」→2回目の板（「合格」）の順に見せる。それでもだめなら、確かめに通った記録に切りかえる
- **正直な表示**：画面に「AIが組み立てた謎（いま生成）」か「AIが組み立てた謎（記録）」かを必ず出す。手で作った謎をAIが作ったように見せない
- **呼び方**：公開ページでは、開いた人の Claude をページから呼ぶ（APIキーを置かない）。サーバー構成では API から呼ぶ。どちらも同じ指示文と同じ確かめの関数を使う

**確かめが実際に見つけたこと**（`tests/fixtures/ai-nets` に、Claude の出力を人の手を加えずに保存し、テスト41で毎回確かめている）
- 胃の謎で、Claude は**肺の文献（空気の通り道の模型）の形だけを借りて胃を表した**。最初の確かめは通ってしまったため、文献ごとの「対象の言葉」の確かめを足し、落ちるようにした
- 体温の謎で、正体の文は「ロボの数字をそろえた」と書いていたのに、確かめは数字が許容内だったので合わせずに通していた。値を指定されたら必ず合わせるように確かめを直した
- 目の中の水の謎では、支える文献がカタログにないため、Claude は肺の謎を組み立て、そのことをつなぎの文と「扱わないこと」に書いた（無理に作らない）

## 開発での Claude Code
- **仕様を先に直す**：`CLAUDE.md` を仕様の正本にし、作者の指摘を受けるたびに、日付と指摘の言葉を添えて仕様を直してから実装した（「何を伝えたい実験か分からない」「回路が浮いて見える」など。作者の指摘で直した記録は `CLAUDE.md` に日付つきで約40件、期間中のコミットは約160）
- **フック**（`.claude/hooks/run-model-tests.mjs`）：モデル・比較器・課題データを編集するたびに、誤差を最悪の端に置いた識別・判定・秘密分離のテストを自動で走らせ、崩れたら編集を止める
- **サブエージェント**（`.claude/agents/`）：「反証役」がテストは通るのに教材として成り立たない条件を探し、「初学者役」（高校で物理などを深く学ばずに医療系へ入った学生）が画面の言葉を点検した。初学者役の指摘で、膜の電気の描き方・ためやすさの言い方などを直した。たとえば、膜の仕掛けろのラウンド2で「戻る時間は同じで高さだけ違う膜をつくるには、通りやすさと容量を逆向きに変える」と書いていた誤りを、説明の食い違いとして指摘され、「同じ向きに小さく（かかる時間＝ためやすさ÷通りやすさは変わらない）」に直した（コミット `8c3b76f`）
- **Skill**（`.claude/skills/add-ai-puzzle-record/`）：「つづきの謎の記録を足す」手順（指示文を出す→Claude に組み立てさせる→確かめる→一度だけ作り直す→手を加えずに記録→テスト41）。この Skill で「脳のまわりの液」の記録を一つ足した（`csf.v4.json`。だれがいつ出力したかを記録に書いている）
- **ブラウザでの通し確認**：Playwright で謎1〜つづきの謎までを自動で通し、暗い・明るい配色、動きを減らす設定、スマートフォンの横向きで、全場面を撮ってはみ出しを調べた。公開ページで Claude が謎を組み立てる場面は、Claude in Chrome で実際に動かして確かめた
- **別のAIによる点検を取捨して直す**：完成間際に、作者が別のAIで行った60項目の点検（人の利用者による試用ではない）を、コードと画面で一つずつ確かめ、事実の誤りと言いすぎは提出前に直し、体験の設計を変える提案は作者が選んだものだけを取り入れた（直す前の版は枝 `stable-1107` に残した）
- **計算で確かめてから画面に出す**：「どのテンポでも見落としは見つかるか」「数字を一つ足すだけでふさげるか」などは、言い切る前に格子で数え、テストにした（17ファイル・152件）

## 対象と前提・検証範囲
- 主な対象は医療系の大学生。ハッカソン期間中の公開デモは大学生以上
- 軟骨は無次元の仮想素材（見本Aが落ち着いた力を 1 N とした値）、血管は2要素ウィンドケッセル、膜は受け身の膜の模型。値は一般的なヒトの値を目安に置いた模型の値で、実在の材料・組織・医療機器や体の値を再現したものではなく、診断・病気の判定・操作手順を示すものでもない
- 制作は作者1名。臨床工学の同僚1名に遊んでもらい、方向性について感想をもらった。学生を対象とした試用は行っていない。理解や興味への効果は設計上の狙いで、検証済みの成果ではない

## このあと
作者が担当している臨床工学コースの「システム工学」と「電気工学」の授業で、補助の教材として使う予定です（コンデンサと抵抗の過渡現象を、膜・血管・軟骨の見立てから入る）。

- **授業での使い方（計画）**：回路の過渡現象に入る前の30分で、謎1を中心に遊び、血管と膜は先生が短く示す。ねらいは「一つの数字が同じでも同じとは限らず、違いを見分ける測り方を自分で選べる」こと。学生での試用はこれから
- **謎を足していく運用**：Claude が題材から謎の候補を組み立て、計算プログラムが確かめ、先生が体の説明と出典の内容を読んで採用する。採用した謎は記録として残し、テストで毎回確かめる（Skill「つづきの謎の記録を足す」）
- **医療系の外へ**：「最後の一つの数字だけで同じと決めると、時間の中の違いを見落とす」ことは、靴底や保護具のクッション、食品のかたさの検査など、押し方で見え方が変わるものに広く当てはまる。ただし、この作品の模型はそれらの実物を表すものではない

## 試行錯誤の経緯
1. **最初の案から作り直した（11/3）**：ポンプ・管・センサの仮想装置で原因を切り分ける実験室を設計したが、作者が伝えたいこと（同じものでも見方で別の面が見える、機械・電気・生体をつなぐ、専門の血管の粘弾性）から外れていたため、素材版に作り直した
2. **一点だけ測ると決着しない**：一つの時刻だけを見る計画では決着しない素材があることを数値試作で見つけ、「どの瞬間を見るか」を選ぶ体験を中心にした
3. **平坦な区間の端点処理**：長く待った点では力がほぼ一定になり、単純な二分法では正しい説明を退ける。実装前の試作で見つけて仕様とテストに入れた
4. **テストが通っても、画面は正しくなかった**：判定の言い方・回路図の配線・説明の向きが計算と食い違っていた。計算の正しさと、画面の値・図・説明の一致は別物と分かり、テストで照合するようにした
5. **教材のページから、ゲームの画面へ**：縦に並ぶ説明とグラフは読む側に回ってしまう、という指摘で、検査ロボとの対決（相手がいる・役割が入れ替わる・測り方が変わる第二ラウンド）を骨格にし、一画面の舞台に作り直した。演出は判定の結果に従わせている
6. **回路を最初に出さない**：「回路に見立てろ」の謎は体と関係がなく浮いて見える、という指摘で外し、電気が本当に出てくる膜で初めて電気の部品の名前を出すようにした。軟骨の二つの謎も一つにまとめ、謎は三つにした
7. **「表せるふり」をやめる**：最初は模型の形をこちらで決め、Claude は値だけを選んでいたため、心臓の「自分で縮む」はたらきを外に出すしかなかった。形ごと Claude に組み立てさせ、確かめをプログラムに任せた
8. **引用は確かめたものだけ**：Claude が出典を書くと架空の文献になりうる。実在と書誌を確かめた文献のカタログから選ばせ、合わない使い方（肺の文献で胃を表す）を落とすようにした
9. **言葉を中学生でも分かるものに**：「時定数」「電位」「末梢」「判定幅」などを言い換え、13px 以下の説明文を置かず、一場面の案内を二〜三文までにした（`CLAUDE.md` 1d に言い換えの表）
10. **別のAIによる点検で見つかった食い違い**：画面では「ロボの手順の 0.5 mV より大きい」と言いながら、証拠に保存する判定は 1 mV で行っていた。言葉と判定を同じ数にそろえ、「もう見落としません」のような言いすぎは「調べた N 通りでは、すり抜けは 0」と数で言うようにした。あわせて、測る前に答えが見えてしまう作り（測る前から全部の波形が出る・挑む前に合否が出る）を、予想→測る→結果が分かれる順に直した
11. **別のAIによる模擬評価を受けて（11/7 夕）**：審査員の目線で採点させると「利用者が何を見つけ、何ができるようになったかが短い時間で伝わらない」と言われた。鍛えなおしの最後に自分の試作品の再検査を置き、デモ動画は統計からではなく「同じと判定したのに、走らせると違う」場面から始めた。動画と説明では、Claude が以前組み立てた記録をいまの計算で確かめ直す画面だと書き分け、「同じ見立て」は「同じ種類の部品の組み合わせ（つなぎ方は違う）」と限定した
