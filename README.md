# mikata-lab（ミカタ・ラボ）

**同じに見える。でも、測り方を変えると違う。**

押して、しばらく待つと区別できない二つの仮想素材。最後の数字は同じでも、途中も同じでしょうか？ その違いを、自分で測り方を考えて見抜く実験室です。見抜いた「時間をかけてやわらぐ変化」は、同じ形の式で電気回路に書け、イオンの移動がつくる細胞の膜の電気にも現れます。「見方」を変えて物理・化学・生物をつなぎ、答えを知らない「味方」のAI（Claude）と一緒に証拠を集めます。

## 作品の筋
「同じ」は、測った条件の中での同じにすぎない。測り方や見方を変えると、違いが見える。

1. 止まっているのに、力が変わる（形を固定しても、押し返す力は時間とともに変わる）
2. いつもの検査（最後の数字だけ）では区別できない。本当に同じ？
3. 途中を見ると違う。でも、押し終わりの一点だけでは理由が決まらない。どこを測れば説明が分かれるかを考える（確かめ方を設計する）
4. 分かったことを使って、検査をすり抜ける素材をつくる
5. 同じBを電気回路で書くと同じ線になる（同じ対象の別の表現）。神経細胞の膜でも同じ形の変化が起きる（別の対象への転用）。膜では、イオンの移動（化学）が電流（電気）になり、膜電位（生物の信号のもと）を変える
6. 何をそろえ、何を変え、何が決め手だったかを、自分の記録から一枚に残す

## どんな体験か
【作成予定：画面の画像】

1. **入口**：ゲルのような軟らかい試験片を試験機で押し込み、深さを保つ。押し板は止まったままなのに、力センサの数字だけが下がる
2. **いつもの検査**：試料Bを押して20秒後の値を、見本Aの基準値と比べる。判定の許容差（±0.03）の内側で「見本と区別できない」。…本当に同じ？
3. **曲線で見抜く**：押す速さを選び、押し終わりの高さを予想して押す。押している間と止めてからの押し返しが曲線で伸びていく
4. **説明を重ねて試す**：「この説明で重ねてみる」で、各説明を押し終わりの高さに合わせた線を重ねる。高さは合っても、途中で外れる説明がある
5. **自分で判断してから検算**：この曲線で合わなくなった説明を自分で選び、そのあとでプログラムの判定（区間計算）を開いて照らし合わせる
6. **答え合わせ**：Bの正体と、決め手になった押し方。自分が測った曲線に、正体の値で計算した線を重ねる
7. **素材をつくる**：つまみで素材をつくり、いつもの検査をすり抜ける素材に挑戦する
8. **見方を変える**：調べたBを電気回路に置きかえると、力と電圧が一本に重なる。次に、神経細胞の膜の一部分を拡大した図で、電流を入れて止め、イオンの通り道を通る正味の電流と膜電位が基準へ戻る様子を、グラフと同じ時刻で見る
9. **今回の発見**：そろえたこと・試した条件・決め手・Bの正体・回路での対応・まだ言えないことが記録から埋まるカードに、一言ずつ足す

## 対象と前提
- 主な対象：医療系の大学生。**ハッカソン期間中の公開デモは大学生以上を対象とします。**
- 素材は**無次元の簡略化した仮想素材**です。実在の物質・組織・医療機器を再現したものではなく、診断や操作手順を示すものでもありません。
- 画面の「Claude（AI）」はAIです。隠れた正解を知らず、あなたと同じ証拠だけで考えます。

## 起動方法
Node.js 22 以上が必要です。
1. `npm install`
2. （任意）`cp .env.example .env` を実行し、`ANTHROPIC_API_KEY` と `CLAUDE_MODEL` を設定。設定しなくても、定型のヒントで最後まで動きます
3. 開発用：`npm run dev`（http://localhost:5173）
4. 本番用：`npm run build` のあと `npm start`（http://localhost:8787）
5. テスト：`npm test`

## Claudeの使い方

### 作品の中のClaude（答えを知らない相棒）
- **言葉→候補の翻訳**：学生の自由な説明（例：「Bの方がねばっこい」）を、検証できる候補に翻訳して確認する。確認した候補は保存し、その後の入力に含める
- **根拠つきの問い返し**：構造化出力（根拠にした記録のID・解釈・次の問い・段階）。根拠の記録は画面で光らせる。文章に数字を書いたら1回だけ書き直させ、それでもだめなら定型の手がかりに戻す
- **判断を先取りしない**：学生が自分で判断するまでは、その曲線の判定をClaudeに渡さない（入力の段階で守る）
- **許可ツールでの観察**：学生が予想を置いて了承した押し方だけを `run_observation` で実行する。了承と違う引数では実行させず、失敗したらサーバーが代わりに実行する
- 隠れた正解・真の値・乱数の種は、Claudeへの入力にも画面のコードにも出さない（テストで確認）
- 実APIでの応答の確認は【作成予定】。鍵がなくても、定型の手がかりで最後まで動く

### 開発でのClaude Code
- `CLAUDE.md` を仕様の正本にし、仕様を先に直してから実装（コミット履歴に残る）
- 設計段階で小さな数値試作を作り、誤差の幅・判定規則・原因の組み合わせを数値で決めた
- フック：モデル・比較器を変更するたびに、最悪ケースの誤差を含む識別・判定・秘密分離のテストを自動実行
- サブエージェント：反証役（区別できない条件を探す）、初学者役（画面の言葉・図を点検。膜の電荷の描き方、容量の言い方、しきい値の説明などを直した）
- 別の目による体験レビューを、コードと計算で照合したうえで採否を決めて反映した（経緯の7〜10）

## 試行錯誤の経緯
1. **最初の案（11/2〜3）**：ポンプ・管・センサの仮想装置で「表示が下がった原因」を切り分ける実験室を設計し、数値試作で識別できることまで確かめました。しかし、作者が本当に伝えたかったこと（同じものでも見方で別の面が見える、機械・電気・生体をつなぐ、見えない性質を確かめる実験を設計する、研究の専門性＝血管の粘弾性）から外れていたため、素材版に作り直しました。コミット履歴にポンプ版の仕様が残っています。
2. **「ゆっくり押すと同じ」は成り立たなかった**：数値試作で、遅く押しても差が残ることが分かり、「押して待つと同じ」に問いを直しました。
3. **一点だけ測ると決着しない盲点**：一つの時刻だけを見る計画では、ある範囲の素材が決着しないことを試作で見つけ、「どの瞬間を見るか」を学生が選ぶ体験そのものを中心にしました。
4. **平坦な区間の端点処理**：長く待った点では力がほぼ一定になり、単純な二分法では正しい説明を退けてしまう不具合を、実装前の試作で見つけて仕様とテストに入れました。
5. **実験計画の支援を二段に**：「帯の重なり」だけで次の観察を勧めると、約1割が決着しませんでした。「誤差を2倍にしても分かれる観察」を区別して解消しました。
6. **見方を広げる**：化学は「イオンの移動が電気をつくる」として細胞の膜の等価回路に入れ、「マイナスの抵抗」の思考実験を「さらに先」に置きました（神経の跳ね上がりの始まりだけを直線で近づけたもので、活動電位そのものの再現ではありません）。
7. **テストが通っても、画面は正しくなかった**：別の目で体験を点検したところ、いつもの検査で「誤差の範囲」と固定表示していた（二つの測定の差は誤差の2倍まで広がる）、回路図の配線が並列部分を短絡していた、速くやわらぐ素材にも「時間がかかる」と説明していた、などの不整合が見つかりました。計算の正しさと、画面の値・図・説明の一致は別物だと分かり、判定の許容差を測定誤差と分けて明示し、回路図の配線と説明の向きもテストで照合するようにしました。
8. **爪の色の戻りを入口に使うのをやめた**：体の入口として考えたものの、血流の現象で、素材の力がやわらぐ仕組みとは別でした。画面の中で「止めたまま力が下がる」を見せる入口に替えました。
9. **判定より先に、自分で判断する**：曲線一本で自動的に決着し、考える場面が短くなっていました。比較器の結果を開く前に、本人が「合わなくなった説明」を選ぶ段を入れ、判定は検算として使うようにしました。
10. **何を相手にしているのかが見えなかった**：四角い素材と回路図だけでは、何を押して何を測っているのか、細胞のどこを見ているのかが想像できない、という指摘を受けました。試験機と試験片の図、神経細胞の膜を拡大した図を主役にし、回路図は対応する説明に回しました。あわせて、押し終わりの高さが同じでも途中が分かれる二つの説明を、線を重ねて試せるようにしました（教材の山場を、文章ではなく線で見せる）。
